# 搬山 · 网盘迁移工具

把文件从一个网盘搬到另一个网盘。本机中转，不落整盘，断了能续。

纯 Python 标准库实现，**不需要 pip 安装任何依赖**。

```
双击 start.bat，或命令行：python -m panmigrate
然后打开 http://127.0.0.1:8899
```

---

## 先说要紧的三件事

**1. 没有"服务端直传"。** 百度、阿里、夸克之间没有任何互信通道，任何迁移工具都必须
在本机或你的服务器上中转。所以速度上限 = 源端下载速度，跟目标盘无关。百度非会员的
下载限速，往往才是真正的瓶颈。

**2. 百度那条路有个岔口，选错了会很别扭。** 官方开放平台认证即时、免费，但规定第三方应用
**只能拥有一个位于 `/apps/` 下的专属文件夹**，读不到你网盘里已有的其它文件 —— 想迁移得先把
文件挪进去。所以默认给你的是扫码登录（走网页登录态），能读全盘、零填写，代价是它属于
非公开接口，会过期、平台改了就失效。两条路都在界面上，随时可切。

**3. 完整性校验用的是"大小 + 首/中/尾抽样比对"，不是全文件 SHA1。** 全文件哈希要
把源端再读一遍，等于流量翻倍，对网盘迁移不划算。抽样能发现绝大多数静默损坏。

## 不用账号的本地演练（命令行，可选）

界面上默认就是真机模式，没有「演示」入口了。想在没有账号的机器上验证链路，用一行命令：

```bash
curl -X POST http://127.0.0.1:8899/api/demo
```

它会把**还没登录凭据**的那一端切成「本地演示」（两边都登录了就不会动你的配置），
并在 `data/demo/source` 生成 6 个演示文件（空文件、22MB 多分片大文件、中文深层路径），
用两个本地文件夹模拟两端网盘，之后在界面上点「扫描整个目录」→「开始迁移」即可。

跑完可以用哈希自行核对：

```bash
python -c "
import hashlib,pathlib
src=pathlib.Path('data/demo/source');dst=pathlib.Path('data/demo/target')
sha=lambda p:hashlib.sha1(p.read_bytes()).hexdigest()
print(all(sha(f)==sha(dst/f.relative_to(src)) for f in src.rglob('*') if f.is_file()))
"
```

## 接入真实网盘：扫码就行

不需要填 client_id、不需要记 token、不需要复制 cookie。**手机上扫一下二维码就完成登录。**

| 端 | 操作 |
|---|---|
| 百度网盘（源） | 点「扫码登录」→ 用手机百度网盘 App 扫 → 手机点确认 |
| 阿里云盘（目标） | 点「扫码登录」→ 用手机阿里云盘 App 扫 → 手机点确认 |

登录成功后凭据自动写进本机 `data/config.json`，下次启动直接可用。

### 四种挑文件的方式

**不用整目录照搬。** 源面板点「浏览」进目录浏览器，勾什么就传什么：

| 方式 | 操作 | 适合 |
|---|---|---|
| 勾单个文件 | 点文件名前的勾选框 → 「加入清单」 | 只要那几个文件 |
| 勾整个文件夹 | 文件夹前面也有勾选框，勾上会**递归展开**成里面的文件 | 某个子目录整包搬走 |
| 按后缀批量勾 | 顶部填 `.jpg,.mp4` → 「全选筛选结果」 | 只要图片 / 只要视频 |
| 粘贴路径 | 「粘贴路径」→ 一行一个路径 → 「按路径加入清单」 | 手里已经有路径清单 |

- 一次可以跨多个目录挑：加完一个目录点面包屑换个目录接着挑，都进同一张清单。
- 文件夹展开上限 5000 个文件，超了会提示并只取前 5000 个；更大的范围请用下面的扫描。
- 「迁移源目录」只决定目标端的**路径结构**（相对它还原目录），**不影响你挑哪些文件**。

**第五种：扫描整个目录**

点「扫描整个目录」会把该目录下所有文件递归列出来（只列目录、不下载）。
大网盘扫一遍可能要很久（实测某个账号根目录 5600+ 个文件、845GB），
扫描过程中可以点「停止扫描」中断。

所有方式的结果都进同一张「文件明细」表，**每一行都有勾选框**，可以最后再调整：
没勾的文件不会被传，进度统计也只算勾中的。表头可以搜索路径、按状态筛选、按大小/名称/状态排序，
每行右边的「移除」只把这个文件从清单里去掉，网盘上的文件不受影响。

### 目标目录

在目标面板点「浏览」，可以进入已有文件夹，也可以点「新建文件夹」当场建一个，
再点「使用当前目录」定为落地位置。

### 扫码登录的性质，得说清楚

它走的是**模拟官方网页端的登录二维码**，不是开放平台的应用授权。所以：

- 好处：零填写、能读整个网盘（不受百度 `/apps` 目录限制）
- 代价：拿到的是网页登录态，会过期；平台改接口时可能失效；严格说属于非公开接口

如果你要的是完全合规、长期稳定，把认证方式切成「官方 OAuth」，代价是要先去开放平台注册应用，
而且百度那边只能读写 `/apps/<应用名>/` 目录。

## 关键设计

| 模块 | 文件 | 职责 |
|---|---|---|
| 适配器层 | `adapters/` | 每家网盘实现 `SourceAdapter`（读）/ `SinkAdapter`（写）|
| 扫码登录 | `qrlogin.py` | 生成二维码、轮询扫码状态、换取登录态 |
| 传输引擎 | `engine.py` | 分片队列、并发、重试退避、续传、校验 |
| 任务库 | `db.py` | SQLite 记录每个文件的分片进度 |
| 调度 | `scheduler.py` | 5 字段 cron 定时增量同步 |
| 界面 | `web/` | 单页，无构建步骤 |
| 依赖 | `vendor/` | 二维码生成库（纯 Python，已内置，不用装）|

**续传的真相来源是服务端，不是本地计数。** 进程被杀后重启，引擎会先问目标端
"这个 upload_id 已经收过哪些分片"（阿里云盘是 `openFile/listUploadedParts`），
只补差额。所以即使本地数据库没来得及记录进度，也不会重传。

**分片在内存里流转**（默认 8MB × 并发 4 ≈ 32MB），不写临时文件。

## 多网盘：怎么再加一家

引擎和界面都不硬编码任何网盘。新增一家只需三步：

1. 在 `panmigrate/adapters/` 下新建文件，实现 `SourceAdapter` 和/或 `SinkAdapter`
2. 在 `adapters/registry.py` 里加一条登记（名称、角色、认证方式、状态、备注）
3. 在 `adapters/__init__.py` 的 `build_source` / `build_sink` 里加两行分支

界面下拉框、授权表单、角色过滤都会自动跟着变。

界面上可选的网盘就这四家（都已双向打通）：**百度、阿里、天翼、夸克**。
城通/迅雷的登记已移除（用户明确不做了）；「本地演示」保留在代码里给自动化测试用，
界面上下发列表时会过滤掉（registry 里的 `hidden` 标记）。

## 变更记录

### 2026-10-24 · 稳定性与操作体验

**修掉的缺陷**

1. **失败任务点了重试没反应**。重试循环拿库里的累计 `attempts` 当条件，一旦
   累计值超过 `retries`，循环一次都进不去 —— 任务静默卡在「失败」，永远不再跑。
   现在每轮重试用独立的轮内计数，累计次数只用于展示。
2. **并发迁同一层新目录会互相撞车**。多个 worker 同时对同一个新目录 `ensure_dir`，
   目标端按「同名目录 refuse」处理，其中一个任务直接失败。现在建目录 + 查同名文件
   加了串行锁。
3. **手动挑的文件会被扫描删掉**。用「加入清单」挑好文件后，再扫描一个子目录，
   旧逻辑会把这次没扫到的 pending 任务当过期记录删掉。现在手动勾选的任务带
   `picked` 标记，扫描不再清理它们。

**新增**

- 「重试失败」按钮：把 `failed` / `paused` 的任务重新排队，**已传分片保留**，
  只补没传完的部分（`POST /api/retry`）。
- 文件明细支持**搜索、状态筛选（未完成/失败/完成/待传）、排序（路径/大小/状态）**，
  「全选」只作用于当前筛选范围内可见的行。
- 「导出报告」下载 CSV（`GET /api/report.csv`，带 BOM，Excel 打开中文不乱码），
  含路径、大小、状态、已传字节、分片进度、累计尝试、错误、更新时间。
- **全局限速** `bandwidth_kbps`（KB/s，0 表示不限）。按累计字节跨线程节流，
  并发数变化时速率不漂；暂停能立刻打断等待。

### 2026-10-24 · 天翼接入（只读）+ 多网盘账号共存

**多网盘账号共存**（切来切去不再丢登录态）

- `data/config.json` 新增 `accounts`：按网盘归档凭据；切 provider 时自动"存旧的、取新的"
- 前端永远拿不到明文：`accounts` 里的密钥同样会被脱敏

**天翼云盘（双向：可作源，也可作目标）**

- 认证只有「网页 Cookie」一条路：`cloud.189.cn/api/**` 未登录统一返回 `InvalidSessionKey`
- 按 folderId 寻址（根 = `-11`），适配器内部做「路径 → folderId」解析并缓存
- 抓登录态的正确姿势（记下来免得再踩）：Edge **默认配置目录不允许开远程调试端口**，
  要用独立 `--user-data-dir`；且**别用强制杀进程**的方式关浏览器，会把没落盘的 Cookie 弄丢
- 写入（上传）已实现并真机验证：`initMultiUpload` → `getMultiUploadUrls` → `PUT` 分片 → `commitMultiUploadFile`，
  参数要 AES-128-ECB 加密、请求要 HMAC-SHA1 签名、会话密钥要 RSA 加密。
  三样算法的纯标准库实现已经在 `panmigrate/crypto.py` 里（FIPS-197 向量验证通过）。
  两个关键坑：字段名是 `parentFolderId`（不是 folderId）；`getMultiUploadUrls` 的 `partInfo`
  要传**分片 md5 的 base64**（传 hex 会导致 PUT 时 S3 网关报 `InvalidDigest`）。

### 2026-10-24 · 打通「迁回百度」（百度作为目标端）

之前百度只能当源，现在两端都能当目标，任意两家之间可以互迁。

**实测出来的百度上传规矩**（都写进代码注释了，换人接手不用再踩一遍）

| 坑 | 表现 | 处理 |
|---|---|---|
| 分片大小 | 固定 4MB，工具里的 part_size 对它无效 | 适配器自己定 4MB，引擎改用会话给的分片大小切数据 |
| 上传域名 | 打到 `pan.baidu.com/rest/2.0/pcs/superfile2` 只是 404 页面 | 走 `c.pcs.baidu.com`，且 URL 必须带 `app_id=250528`，否则 `31024 app id is empty` |
| 预上传 block_list | 空数组报 errno=2；要求数量与分片数一致 | 先塞占位 md5（全 0），真实 md5 在 `create` 时提交 —— 省掉「为算哈希把整个文件先下一遍」 |
| 已存在目录 | `api/create` **不报错但会改名**（`xxx_20261024_224946`） | 建目录前必须先查存在性，否则凭空多出垃圾目录 |
| 0 字节文件 | `api/create` 返回 errno=10 | 明确跳过并标注原因，不再假装成功 |
| 列表里的 md5 | 可能是混淆值（含 `g`/`h` 之类非 hex 字符） | 永不拿它当校验依据，一律回读抽样比对 |
| 刚写完立刻下载 | 偶发 403 `31326 user is not authorized` | 抽样校验自带一次强制刷新直链的重试 |

**真机验证**：本地 950B 中文文件 + 5MB 双分片 → 百度 `/panmigrate-验证/引擎测试`，
大小 + 3 处抽样比对全部通过，耗时 10.3 秒；验证后测试文件已从网盘删除。

**附带**：清理网盘文件需要 `bdstoken`（不带会返回 8001），这条也记着，后面做「覆盖/删除」会用上。

**目标空间预检**

- 「迁移」卡片会显示「目标剩余 105 GB / 共 105 GB · 本次还需 X」，不够时标红
- 阿里走 `POST /v2/drive/get`（网页态**没有** `adrive` 前缀，加了就 404）；百度走 `/api/quota`
  （它返回的 `free` 实测等于 total，剩余空间得自己算）
- 容量 60 秒缓存，不会每次轮询都打网盘接口

### 2026-10-25 · 改名「搬山」+ 界面重做（方向箭头 / 预设 / 视觉包装）

**改名**：项目叫 **搬山**（愚公移山，一山一山搬）。logo 是「山 + 向右的箭头」的内联 SVG，

**用箭头表达迁移方向，不再靠左右位置区分**

- 实现上只切 `#ends` 的 `rev` 类（CSS `order` 反转视觉顺序），**DOM 和 role 语义不动**，
  所以 `panel-source` / `panel-target` 及其内部 `${role}-xxx` 绑定完全不受影响。
- 角色由面板标题（「源 · 从这里读取」/「目标 · 写入到这里」）和卡片左侧色条
  （源=蓝、目标=绿）标识，方向记忆存 localStorage。
- 注意：切方向**不会**互换两端配置（只是视觉位置变化），别在文案里说「配置已互换」。

**设置改成预设档 + 下移**

- 预设四档：稳妥 / 均衡（推荐）/ 极速 / 省流，外加一个「自定义」状态卡（不可点）。
- **「均衡」的数值对齐引擎默认档**（file 2 / part 2 / 10MB / 不限速），否则用户一次没改过
  却显示「自定义」，会以为坏了。
- 并发、分片、限速这些看不懂的项收进「高级设置（一般不用改）」的折叠里；
  设置整块从原来靠上的位置**移到文件明细之后**。

**视觉与节奏**

### 2026-10-24 · 自选文件、秒传命中、自动化测试

**新增：挑文件的多种方式**（见上文「四种挑文件的方式」）

- 文件夹也能勾选，递归展开后整体加入清单（上限 5000 文件）
- 按后缀筛选 + 一键全选筛选结果
- 粘贴路径批量加入（文件、文件夹混着粘都行，找不到的会列出来）
- 清单每行可「移除」，只删任务记录不动云端文件

**修掉的缺陷**

1. **阿里云盘「服务端已有该文件」被判成失败**。`openFile/create` 在文件已存在时
   只回 `file_id`，不回 `upload_id`，旧代码直接抛错。现在按**秒传命中**处理：
   0 分片、直接完成，并照常做抽样校验。
   实测：3 个此前失败的文件重试后全部 0 流量完成，校验通过。
2. **合并分片后目录缓存不失效**，同目录的下一个文件还会以为没有同名文件，
   白撞一次「已存在」。现在 `complete` 后清空目录缓存。
3. **按路径加入时父目录不存在会整批失败**，现在只记一条「没找到」。
4. **配置脱敏里 `has_token` 永远是 False**（先把密钥清空再判断），前端因此永远显示未授权。

## 已知限制

- 百度 → 其它：扫码或 cookie 模式可读全盘，但属网页登录态，时刻可能变
- 两端都支持，所以任意两家之间都能互迁（含「阿里 → 百度」）
- **天翼、夸克已双向支持**（读/写都通）；城通/迅雷的登记已按需求移除
- **界面上只有四家可选**：百度、阿里、天翼、夸克（本地演示仅供测试，界面不显示）
- **百度作为目标**：分片固定 4MB（不受工具里 part_size 影响）；**0 字节文件百度接口不支持**，
  会被跳过并在备注里标注；百度列表里的 `md5` 字段可能是混淆值，校验一律按字节抽样比对
- **天翼作为目标**：分片固定 10MB；**0 字节文件天翼接口不支持**，会被跳过并标注
- **夸克作为目标**：分片固定 4MB；**0 字节文件夸克接口不支持**，会被跳过并标注；上传前要
  算整个文件的 md5/sha1（秒传校验），所以夸克作为目标端时单个文件的上传会多一遍本地哈希
- 阿里 → 任意：作为源可用，但下载链接接口依赖权限
- 主动秒传（`proof_code` RSA 签名）仍未实现：只有服务端自己判定「这个文件已存在」时才会
  0 流量收下；全新的文件依旧是真实上传，不影响正确性
- 网盘的 refresh_token 每次续期都会轮换，工具会自动回写配置，不要手动改 data/config.json
- `/api/demo` 只在某一端还没登录时才会把它切成演示盘，不会覆盖已登录的账号（界面上已无入口，纯命令行备用）
- 凭据以明文存在 `data/config.json`，只监听 `127.0.0.1`，不要改成 `0.0.0.0` 暴露到公网
