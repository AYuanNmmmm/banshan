## 二、重点开源项目详解

### 1. Alist（alist-org/alist）★ 网盘聚合标杆

- **GitHub**：`https://github.com/AlistGo/alist`（原 alist-org/alist）
- **语言**：Go + Vue/Ant Design
- **定位**：把几十种网盘统一聚合到一个网页，支持浏览、预览、上传、下载、**跨存储复制/移动**、WebDAV、离线下载
- **支持网盘**：阿里云盘、百度、夸克、天翼、迅雷、蓝奏、115、123、OneDrive、Google Drive 等 50+ 种

**可借鉴的实现方案**：
- **驱动化架构**：每个网盘一个 driver，实现统一的文件接口（List/Get/Link/Mkdir/Move/Copy/Delete/Upload）。和「搬山」的 `SourceAdapter`/`SinkAdapter` 分层思路一致，但 Alist 用「存储驱动 + 统一 File 接口」更彻底，任何两个 driver 之间都能 Copy/Move（即跨网盘转存）。
- **跨网盘复制**：Alist 的「在 A 网盘和 B 网盘之间复制文件」正是「搬山」的核心诉求，其实现是「服务端流式中转」（A 下载 → B 上传），和「搬山」的流式转发不落盘思路一致。
- **秒传优化**：部分驱动实现了服务端秒传（如阿里 proof_code），可省流量。

> 启发：可以把「搬山」的 source/sink 从「两角色」泛化成「多 driver」，天然支持 N 对 N 迁移。

### 2. QuarkPan（lich0821/QuarkPan）★ 夸克扫码登录直接可用

- **GitHub**：`https://github.com/lich0821/QuarkPan`
- **语言**：Python
- **定位**：夸克网盘完整 Python 客户端 + CLI，含登录、文件管理、上传下载、分享转存、断点续传

**扫码登录实现（已实测核对，与「搬山」问题直接相关）**：

```python
# 1) 获取二维码 token
GET https://uop.quark.cn/cas/ajax/getTokenForQrcodeLogin
    ?client_id=532&v=1.2&request_id=<uuid>
# → data.members.token

# 2) 二维码 URL（完整参数，缺了会扫码失败/提示过期）
https://su.quark.cn/4_eMHBJ?token={token}&client_id=532&ssb=weblogin
    &uc_param_str=
    &uc_biz_str=S%3Acustom%7COPT%3ASAREA%400%7COPT%3AIMMERSIVE%401%7COPT%3ABACK_BTN_STYLE%400

# 3) 轮询登录状态（2 秒间隔，300 秒超时）
GET https://uop.quark.cn/cas/ajax/getServiceTicketByQrcodeToken
    ?client_id=532&v=1.2&token={token}&request_id=<uuid>
# 成功：status==2000000 且 data.members.service_ticket 存在
# 过期/失败：status in (50004002,50004003,50004004) 或 message 含 expired/failed/error/timeout/invalid
# 等待：status==50004001

# 4) 换 cookie
GET https://pan.quark.cn/account/info?st={service_ticket}&lw=scan
# → Set-Cookie 里含 __pus / __puus 等
```

**可借鉴点**：夸克上传的 6 步协议（预上传 → update/hash → 逐分片 auth → PUT OSS → 合并 → finish）、断点续传、md5/sha1 顺序累积，与「搬山」现有 `quark.py` 实现一致，可交叉验证。

### 3. aliyundrive / aliyunpan ★ 阿里秒传 proof_code

- **GitHub**：`https://github.com/jakeslee/aliyundrive`（Go）、`https://github.com/wxy1343/aliyunpan`（Python）
- **语言**：Go / Python

**秒传实现（两阶段模型，BoxPlayer 源码解析）**：

```
POST /v2/file/create_with_proof
  第一次：只带 pre_hash（文件前 1KB 的 SHA1）→ 快速探测是否可秒传
    → 命中：返回 code=PreHashMatched
    → 未命中：继续算整文件 SHA1 + proof_code
  第二次：带完整 content_hash + proof_code
    → rapid_upload=true → 秒传成功（0 流量）
    → 否则返回 part_info_list → 走普通分片上传
```

- **proof_code** = base64（从文件随机 8 字节 + 校验数据），RSA 相关
- **关键结论**：秒传命中率取决于目标盘是否已有该内容。跨厂商迁移（百度→阿里）时，阿里侧通常没有该文件，**命中率≈0**，收益极低 —— 这正是「搬山」此前「秒传暂缓」的判断依据，本报告再次印证。

### 4. Quark2Baidu（elitever/Quark2Baidu）★ 跨网盘秒传转存

- **GitHub**：`https://github.com/elitever/Quark2Baidu`
- **语言**：Python
- **定位**：夸克 → 百度网盘的秒传转存 CLI（TUI 界面）

**可借鉴点**：
- **秒传转存**：利用百度网盘秒传（`rapid_upload`）避免重复下载上传大文件 —— 从夸克取文件 md5/sha1 → 百度侧 `precreate` 秒传。
- **递归目录选择**：按 `r` 键递归选择整个文件夹并保持目录结构。
- **配置持久化**：Cookie + 设置存 config.json，下次免输入。
- **并发控制**：`concurrency`（默认 3）线程并发转存。

---

### 5. Cloudreve ★ 分片/断点续传协议参考

- **GitHub**：`https://github.com/cloudreve/Cloudreve`
- **语言**：Go + React
- **定位**：自建网盘系统，多云存储后端 + 虚拟文件系统

**统一上传协议（可借鉴）**：
```
1. Create upload session → {session_id, chunk_size, upload_urls[], credential, expires}
2. Upload chunks（chunk_concurrency 并发）
3. Complete upload（按存储类型：本地/OSS CompleteMultipartUpload 等）
```
- **分片大小 16MB**（平衡内存与传输效率）
- **断点续传**：session_id 持久化，重连后补传未完成分片
- 支持客户端直传（不过服务器中转）、流式加密（AES-256-CTR）

### 6. BaiduYunToAliYun（b2a）★ 迁移专用

- **GitHub**：`https://github.com/lqclight/BaiduYunToAliYun`
- **语言**：Python
- **定位**：百度 → 阿里的定向迁移，依赖 `aigpy`、`BaiduPCS`、`aliyundrive-uploader`、`aliyunpan` 等库

**可借鉴点**：迁移「先下载到本地 → 再上传」的朴素实现（不流式），可作对比参照（「搬山」的流式不落盘更优）。

## 三、对「搬山」的具体改进建议

1. **夸克扫码登录**（已完成）：补齐二维码 URL 的 `uc_param_str` + `uc_biz_str` 参数，补全过期状态码 50004002 判断 —— 这是「手机提示二维码过期」的根因。

2. **秒传**：跨厂商迁移秒传命中率≈0，不建议投入。若未来做「同网盘搬家」（阿里→阿里换账号），才需要实现 proof_code。

3. **架构泛化**：可参考 Alist 把 source/sink 泛化为「多 driver + 统一 File 接口」，天然支持任意两网盘互迁，而不是现在固定的「源/目标」两角色。

4. **天翼云盘**：Alist 有完整天翼驱动（Go），可交叉验证「搬山」的天翼上传协议（sessionKey + RSA + AES + HMAC 签名链）。

5. **分片大小**：Cloudreve 用 16MB，Alist 各家驱动分片大小不一；「搬山」当前百度/夸克固定 4MB、天翼固定 10MB，是网盘服务端限制，不可改，但可参考 Cloudreve 的「统一 chunk_size + 断点续传 session」思路优化续传体验。
