## 一、项目是什么

本地网页版网盘迁移工具：**从 A 网盘读文件 → 写到 B 网盘**，支持断点续传、限量重试、完整性抽样校验。

- **产物**：`dist/搬山.exe`（单文件，双击即用，零外部依赖）
- **数据目录**：`%APPDATA%\panmigrate`（便携模式：exe 旁放 `panmigrate-data/`）
- **支持网盘**：百度 / 阿里云盘 / 夸克 / 天翼（双向）
- **技术栈**：纯 Python 标准库 + 原生 HTML/CSS/JS（无框架、无构建）

代码规模：后端 ~7400 行，前端 ~4200 行（`style.css` 1685 / `app.js` 1982）。

## 三、设计规范（改样式前先看这里）

### 字号只有 5 档

| 变量 | 值 | 用途 |
|---|---|---|
| `--fs-2xs` | 11px | 极小标注、计数徽章 |
| `--fs-xs` | 12px | 标题条标签、按钮小字 |
| `--fs-sm` | 12.5px | 正文、提示、表单 |
| `--fs-md` | 13px | 卡片内小标题 |
| `--fs-lg` | 14.5px | 卡片主标题 |

### 间距只有 3 档

| 用途 | 值 |
|---|---|
| 标题条上方 | 16px |
| 标题条 → 卡片 | **6px** |
| 卡片之间 / 排之间 | 16px |
| 卡片内边距 | 18px（`.browser` 除外，它内部自己排） |

### 颜色

| 用途 | 值 |
|---|---|
| 页面底 | `#f4f6f9` |
| 卡片 | `#fff` |
| **折叠条底** | `#e9f0fa`（必须明显区别于页面底） |
| 折叠条边框 | `#d5e0ef` |
| 标题条文字 | `#5c6a7e` |
| 主色 | `--accent: #2563eb` |
| 目标端标识 | `#7c5cd6`（紫） |

### 折叠态规则

1. 卡片切浅蓝底 + 淡边框 + 无阴影，标题转灰
2. **操作按钮全部收起**（视图切换、批量操作、说明标签都不露）
3. 已选清单是例外：收起后仍露「表头 + 3 行」，因为只剩按钮没用
4. `.card.is-folded .fold-body { display: none !important }` —— 新增板块若要例外，必须用更高优先级覆盖

## 四、关键实现点

| 功能 | 实现要点 |
|---|---|
| 文件选择 | 内联在主界面（`#browser`），无二级弹窗；目标端独立 `loadTargetDir` 只列文件夹 |
| 格式筛选 | 候选下拉，扩展名从当前目录自动提取 + 关键词过滤候选，**不手输** |
| 方向条 | 源/目标卡 + 中间圆形交换按钮；「设置/去登录/收起」同一入口切换 |
| 设置面板 | **浮层**（`position: absolute`），展开不挤压下方；点外部自动收起 |
| 折叠联动 | `FOLD_GROUPS = [["browser","tdir"], ["settings","log"]]`，点任一同步 |
| 单文件折叠 | `job` / `picked` 各自独立 |

## 五、历史包袱（下次改动前必看）

### 1. CSS 已做过一轮归并（2026-10-25）

**做完的**：用浏览器实测每条选择器能否在当前 DOM 匹配，删掉 70 个**确定失效**的规则块。

- 1685 → **1554 行**，大括号配平 588/588
- **像素级回归验证：归并前后截图完全一致（差异区域 None）**
- 删除的模块：`.stage`/`.ends`/`.swap*`（v1 方向箭头区）、`.run-card`、`.stats`/`.stat`（v1 统计方块）、
  `.pill`、`.dlg-views`（旧弹窗）、`.shell`/`.side`（v2 侧栏）、`.setup.mini`、`.br-tabs`（v3 tab）、
  `.job-sep`、`.ico`、`td.name`/`td.num`

**没敢自动删的**（重要）：
- **状态类**：`.on`/`.running`/`.picked`/`.warn`/`.busy`… 当前页面恰好没触发，但运行时需要
- **依赖数据类型的**：`.fico[data-k="video|audio|archive|file"]`、`.dirlist.grid`（图标视图）——
  测试目录里只有 jpg，静态检查会误判为"未使用"
- **备份**：`.agent-runs/2026-10-25/css-merge-backup/`（三个前端文件的归并前版本）

**遗留**：仍有 ~100 个选择器被重复定义（十几轮覆盖层层叠加）。试过自动合并，但脚本处理
`@media` 嵌套不可靠（括号不配平），已放弃。若要继续瘦身，建议按模块人工重写而非脚本合并。

### 2. 已知易踩的坑

| 现象 | 原因 |
|---|---|
| 折叠后仍留一个空框 | 只隐藏了 body，卡片标题行还在；或某处 `min-height` 没清 |
| `!important` 吞掉内容 | `.card.is-folded .fold-body` 带了 `!important`，例外必须显式覆盖 |
| 按钮文案不跟着变 | 折叠状态存在 `panelFold`（source/target），DOM id 是 `src/dst`，两套键名容易混 |
| 点一下没反应 | 按钮点击冒泡到 document 的「点外部收起」逻辑，需 `stopPropagation` |
| 页面全空 + 无报错 | JS 语法错误（如 `const` 重复声明）会让整个脚本不执行，必须先看控制台 |

## 六、会话中修复的功能性问题

| 问题 | 根因 | 修复 |
|---|---|---|
| 阿里 → 百度报 `drive_id and share_id are both nil` | `_download_url` 漏传 `drive_id` | 补参数 + `ensure_drive()`；`complete`/`get_file_by_id` 同步补齐 |
| 阿里上传 `PartNotSequential` | 阿里是 sequential multipart | `SinkAdapter.sequential_parts` 能力位，引擎压并发到 1 并按序 |
| 进度显示 395MB / 总 263MB | `_bytes_live` 重复计算 + 上传失败不回退 | 拆成"未落库字节" + "速度采样字节"两个计数器 |
| 「已全部处理完」但还在传 | 状态统计漏了 running | 优先看 `summary.running` |
| 暂停后按钮灰 40 秒 | worker 卡在分片读取 | 读取循环每 64KB 检查停止信号（`ReadCancelled`） |
| 任务卡在 running | 强杀后未复位 | `db.reset_running()` 启动时退回 pending |
| 天翼登录要装 node | 依赖 `tylogin.js` | 纯 Python CDP 客户端（`cdp.py`），WebSocket 手写 |
| 天翼「已登录」误判 | 匿名 cookie 也有 `COOKIE_LOGIN_USER` | 改查 `getUserSizeInfo` 是否返回 `account` |
